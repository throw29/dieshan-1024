## 1. 文档目的

本文记录《叠山 · 1024》的产品定义、完整游戏规则、交互规格、状态机与验收标准，作为产品设计、前端实现和后续迭代的共同依据。

## 2. 产品定义

| 维度 | 定义 |
| --- | --- |
| 产品名称 | 叠山 · 1024 |
| 产品类型 | 单人数字合并益智游戏 |
| 核心目标 | 通过合并相同数字，在棋盘上拼出 `1024` |
| 目标用户 | 喜欢轻量益智、数字策略与东方视觉风格的桌面及移动端用户 |
| 使用场景 | 碎片时间、休闲放松、短局挑战 |
| 使用门槛 | 无需注册、无需联网、打开即玩 |
| 单局时长 | 约 5–20 分钟，视棋盘大小和玩家目标而定 |
| 平台形态 | 响应式 Web 页面，可作为静态页面部署 |
| 核心体验词 | 克制、沉静、手作感、逐步登高 |

### 体验目标

1. **一眼可懂**：首次进入时，通过标题文案、棋盘目标和操作提示理解基本玩法。
2. **安静专注**：视觉不使用高饱和冲突色，动效服务于状态反馈，不制造额外噪音。
3. **每一步有回应**：移动、合并、得分、无效方向都有清晰但轻量的反馈。
4. **有终点的攀登**：`1024` 是明确的阶段性目标；达成后仍可继续探索更高峰。
5. **移动端不妥协**：小屏布局保留完整棋盘、得分、操作和目标信息。

### 非目标

当前版本明确不包含以下能力：

- 账号体系、联网对战、排行榜或云存档；
- 广告、内购、付费系统；
- 音效、背景音乐；
- 撤销、提示、自动求解器；
- 关卡系统或每日挑战；
- 正式无障碍认证。

| 术语 | 含义 |

| 越峰 | 达成 `1024` 后继续合并出更高数字 |

## 4. 核心循环

```text
┌─────────────────────────────────────────────────────┐
│                    开始一局                          │
│           生成两枚初始方块，得分归零                   │
└──────────────────────┬──────────────────────────────┘
                       ↓
┌─────────────────────────────────────────────────────┐
│  玩家输入方向（键盘 / 滑动 / 拖动）                    │
└──────────────────────┬──────────────────────────────┘
                       ↓
              ┌────────────────┐
              │  是否存在有效移动？│
              └───────┬────────┘
            否        │         是
        ┌─────────────┘         └───────────────────────┐
        ↓                                               ↓
  棋盘回弹反馈                               所有方块向目标方向压缩
  不生成、不计分、不计手数                   同数方块按规则合并
                                                      ↓
                                             合并数值累加至得分
                                                      ↓
                                             随机空位生成 1 / 2 / 4
                                                      ↓

                                        │  是否合出 1024？           │
                                        └─────────────┬─────────────┘
                                                 是   │   否
                                        ┌─────────────┘   └──────────────┐
                                        ↓                                ↓
                                 弹出「山成」                 是否仍有可行移动？
                                                                 否 │ 是
                                                          ┌────────┘  └─────┐
                                                          ↓                  ↓
                                                   弹出「山止」         回到输入状态
```

## 5. 棋盘与模式

### 5.1 棋盘规格

- 提供两种正方形棋盘：
  - `4 × 4`，共 16 格；
  - `5 × 5`，共 25 格。
- 初始状态为空；开局时生成两枚随机方块，位置在所有格子中均匀随机，且互不重叠。
- 方块值始终为 2 的幂：`1` 和 `2` 为初始低值，合并后产生 `4, 8, 16, ...`。

### 5.2 模式差异

| 项目 | 4 × 4 | 5 × 5 |
| --- | --- | --- |
| 格数 | 16 | 25 |
| 定位 | 经典、紧凑 | 从容、适合长线 |
| 最佳成绩 | 独立记录 | 独立记录 |
| 初始布局 | 两枚随机方块 | 两枚随机方块 |
| 目标 | 合出 `1024` | 合出 `1024` |

### 5.3 切换规则

- 点击「四格」或「五格」立即重置当前对局并开始新局。
- 切换后的尺寸会被记住，下次打开页面时恢复。
- 两种尺寸的最佳成绩互不影响。
- 点击当前已激活的尺寸按钮不会重置对局；重置请使用「另起一局」。

## 6. 移动与合并规则

### 6.1 移动

玩家每次输入一个方向，棋盘上所有方块同时向该方向移动，直到：

1. 到达棋盘边缘；或
2. 前方被另一枚方块阻挡。

方块不会穿过彼此。若某行/列中没有任何方块可以移动或合并，则该方向的输入被视为无效移动。

### 6.2 合并

同一行或同一列中，两个相邻且数值相同的方块会在该次移动中合并：

- 新方块的数值为两者之和；
- 新方块占据两者移动方向上的目标位置；
- 每个方块每手最多参与一次合并；
- 合并产生的新方块不能在同一手内再次参与合并。

### 6.3 合并顺序

算法按“靠近目标边缘的方块优先”处理每条线：

- 向左移动时，从左向右扫描；
- 向右移动时，从右向左扫描；
- 向上移动时，从上向下扫描；
- 向下移动时，从下向上扫描。

这保证了合并配对顺序符合直觉，也符合经典 2048 规则。

### 6.4 规则示例

| 初始行（从左到右） | 操作 | 结果 | 说明 |
| --- | --- | --- | --- |
| `2, 2, 4, 0` | 向左 | `4, 4, 0, 0` | 前两枚先合成 `4`，但不与后面的原有 `4` 再次合并 |
| `2, 2, 2, 2` | 向左 | `4, 4, 0, 0` | 两两合并，不能串成 `8` |
| `4, 0, 0, 4` | 向左 | `8, 0, 0, 0` | 跨过空格后相邻，可以合并 |
| `2, 4, 8, 16` | 向左 | 不变 | 没有可移动空间或可合并项 |
| `2, 2, 4, 8` | 向右 | `0, 4, 4, 8` | 右侧的 `4`、`8` 先靠到边缘，左端两枚 `2` 合并后停在 `4` 的左侧 |
| `4, 4, 8, 0` | 向右 | `0, 0, 8, 8` | 两枚 `4` 合成 `8`，与原有 `8` 相邻但不再次合并 |

> 最后两例的“结果”以整行向右压缩后的位序为准。

### 6.5 无效移动

如果输入方向不会导致任何方块移位或合并：

- 不生成新方块；
- 不计分；
- 不增加手数；
- 棋盘边框播放一次轻微的回弹/轻推动画。

## 7. 随机生成规则

每次**有效移动**（包括有合并和无合并的移动）并完成棋盘更新后，在随机空位生成一枚新方块。

### 7.1 生成位置

- 枚举所有空单元格；
- 使用均匀随机选择其中一个位置；
- 新方块不会覆盖已有方块。

### 7.2 生成数值

| 数值 | 权重 |
| --- | ---: |
| `1` | 8% |
| `2` | 80% |
| `4` | 12% |

期望生成值为：

```text
0.08 × 1 + 0.80 × 2 + 0.12 × 4 = 2.16
```

`1` 为游戏增加一层“奇数低值”元素，但不改变所有可合成数字仍为 2 的幂这一核心结构；`4` 则提供更快的开局节奏。

### 7.3 生成时机

生成的判定在合并提交之后进行。若一次移动同时完成 `1024` 与棋盘填满，系统优先展示胜利状态；玩家继续后若已无可行移动，再进入结束状态。

## 8. 计分规则

- 初始得分为 `0`。
- 每次合并获得等同于新方块数值的分数：
  - `2 + 2 → 4`，得 `4` 分；
  - `8 + 8 → 16`，得 `16` 分；
  - 两次合并 `4 + 8`，共得 `12` 分。
- 无合并的平移不得分。
- 生成新方块不得分。
- 得分只在当前对局内累计；新开局归零。
- 每种棋盘的“最佳成绩”取该尺寸历史最高分，存储在浏览器本地。

### 最佳成绩更新

- 只在当前得分超过已记录的最佳成绩时写入。
- 保存成功后刷新页面仍会显示。
- 本地存储不可用时不阻塞游戏，仅失去跨刷新记忆。

## 9. 胜利、继续与失败

### 9.1 胜利条件

一次有效移动结算后，若棋盘上存在数值 **大于等于 `1024`** 的方块，则触发首次胜利：

- 标记本局已胜利；
- 显示「山成」弹窗；
- 弹窗展示本局得分和最高方块；
- 提供「继续叠山」和「另起一局」两个操作。
- 每局仅主动展示一次胜利弹窗。

继续游戏后，胜利标记保持，合出更高的 `2048` 等不会重复弹出胜利界面。

### 9.2 达到目标后的视觉

- `1024` 方块具有独立的鎏金材质和流光动画。
- 超过 `1024` 的方块（如 `2048`、`4096`）使用深墨底鎏金字风格。
- 山径进度到达最后一格后高亮目标位置，文案改为「登峰 · 1024」或「越峰 · 数值」。

### 9.3 失败条件

当同时满足以下条件时，当前对局结束：

1. 棋盘没有任何空位；
2. 横向、纵向均不存在相邻且数值相同的方块。

此时：

- 弹出「山止」界面；
- 展示本局得分和最高方块；
- 不提供继续游戏，只可另起一局；
- 无法再接受键盘或滑动输入。

### 9.4 胜利与失败同时发生

虽然概率较低，但一次移动及新方块生成后可能同时满足“已合出 1024”和“无可行移动”：

1. 优先展示胜利弹窗；
2. 玩家选择继续后，系统再次检测可行移动；
3. 若无路可走，则随后展示失败弹窗。

## 10. 交互规格

### 10.1 键盘

| 按键 | 动作 |
| --- | --- |
| `ArrowLeft` / `A` | 向左移动 |
| `ArrowRight` / `D` | 向右移动 |
| `ArrowUp` / `W` | 向上移动 |
| `ArrowDown` / `S` | 向下移动 |
| `Esc` | 在胜利弹窗中执行「继续叠山」 |
| `Tab` | 在弹窗按钮间移动焦点，焦点被限制在弹窗内 |

- 带有 `Ctrl`、`Meta` 或 `Alt` 修饰键时，不触发游戏移动。
- 方向键输入会阻止页面滚动，避免游戏按键导致页面跳动。

### 10.2 指针 / 触摸

- 按住棋盘并向任意方向移动，松开时判定滑动方向。
- 主方向按横向/纵向位移绝对值较大的一轴决定。
- 滑动距离小于 **24px** 时不执行移动。
- 支持鼠标拖动与触摸滑动。
- 棋盘区域设置 `touch-action: none`，避免滑动棋盘时页面滚动。
- 输入开始时棋盘获得焦点，方便后续键盘操作。

### 10.3 动画期间

- 一次移动的滑动、合并提交、落子与状态检查完成前，输入被锁定。
- 锁定期间的分页操作不会中断当前对局。
- 如果在该期间点击「另起一局」或切换尺寸，系统通过代际计数使旧异步流程失效，避免旧动画污染新局。

### 10.4 无效输入反馈

- 棋盘整体向左/右做几像素的轻微回弹，时长约 300ms。
- 不播放音效；不弹出 toast。
- 读屏环境会播报“此方向无法移动”。

## 12. 状态机

### 12.1 核心状态

| 状态 | 描述 | 可接受输入 |
| --- | --- | --- |
| `idle` | 等待玩家输入 | 方向键、滑动、按钮 |
| `animating` | 正在执行移动与动画 | 无（输入锁定） |
| `win-overlay` | 胜利弹窗开启 | 继续、另起一局、`Esc` |
| `lose-overlay` | 失败弹窗开启 | 另起一局 |
| `starting` | 新局初始化 | 按钮（极短） |

### 12.2 主要转移

```text
idle --有效方向--> animating --结算--> idle
animating --合出 1024--> win-overlay
animating --无空位且无可合并--> lose-overlay
idle --无效方向--> idle（回弹）
win-overlay --继续--> idle 或 lose-overlay
win-overlay --另起一局--> starting --> idle
lose-overlay --另起一局--> starting --> idle
idle --切换尺寸--> starting --> idle
```

### 12.3 新局

以下操作会重新开始：

- 点击「另起一局」；
- 在胜利 / 失败弹窗中确认另起一局；
- 切换到另一种棋盘尺寸；
- 清除本地数据后重新加载页面。

新局会：

- 清空棋盘；
- 得分和手数归零；
- 取消胜利 / 失败状态；
- 载入当前尺寸的最佳成绩；
- 生成两枚初始方块。

## 13. 反馈与动效

| 事件 | 反馈 | 时长（常规模式） |
| --- | --- | ---: |
| 页面载入 | 刊头、信息栏、棋盘依次上浮淡入 | 850–950ms |
| 方块移动 | 使用 `translate3d` 平滑滑动 | 150ms |
| 合并 | 汇合后数值更新，方块轻微放大回弹 | 300ms |
| 新方块出现 | 缩放并淡入 | 250ms |
| 得分增加 | 数字轻微上跳，旁侧出现 `+N` | 360–900ms |
| 无效移动 | 棋盘轻微回弹 | 300ms |
| 胜利 / 失败弹层 | 遮罩淡入、卡片上浮、朱砂印章落下 | 350/550/600ms |
| 1024 方块 | 鎏金底色上的缓慢流光 | 5.5s 循环 |

在 `prefers-reduced-motion: reduce` 下，动画和过渡会缩短至近乎即时；游戏逻辑与反馈仍在。

## 15. 响应式与无障碍要求

### 15.1 响应式

- 棋盘必须始终为正方形，比例不因视口变化而拉伸。
- 在手机上，得分、尺寸选择、新局按钮与棋盘都需要保持可读、可点。
- 在较矮的桌面视口中，压缩刊头并缩小棋盘，优先保证棋盘完整可见。
- 小屏隐藏冗长说明，保留一条简短的行棋提示。

具体断点与布局见 [设计规范](DESIGN_SYSTEM.md) 和 [前端技术文档](FRONTEND.md)。

### 15.2 无障碍要求

- 所有操作按钮可通过键盘到达并触发。
- 棋盘具备可理解的 `aria-label` 与操作说明。
- 动态得分、胜利、失败和新局通过 `aria-live` 播报。
- 模态弹窗打开后，焦点进入弹窗，背景内容不可聚焦。
- 焦点状态清晰可见。
- 不仅依赖颜色传达胜利/失败或数值变化，有文字和布局辅助。

## 16. 验收标准

### 16.1 功能

- [x] 页面初次加载时，4 × 4 棋盘中出现两枚不同的方块。
- [x] 方向键、WASD、鼠标拖动和触摸滑动均可触发有效移动。
- [x] 每个方块每手只合并一次。

## 17. 后续可扩展方向

以下方向**不属于**当前版本，但对未来演进有价值：

1. 撤销一步（需要对每次操作保存完整棋盘快照）。
2. 对局自动保存与恢复。
3. 音效与开关，木质轻响与合并回声。
4. 在线排行榜与跨设备最佳成绩。
5. 每日固定牌序挑战。
6. 可切换主题（例如月夜、朱砂、青瓷）。
7. 历史回放与分享图生成。
8. PWA 安装与离线缓存。
9. 更多棋盘尺寸（6 × 6 等，需要同步调整排版与存储模式）。
10. 更强的无障碍模式，例如棋盘格读数面板。
