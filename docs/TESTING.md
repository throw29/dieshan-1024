## 1. 测试范围

本轮测试针对发布前的单文件版本 `index.html`，覆盖：

- 页面初始化与渲染；
- 数字合并、移动、计分与随机生成；
- 键盘、鼠标、触摸滑动输入；
- 无效移动处理；
- 4 × 4 / 5 × 5 棋盘切换；
- 胜利、继续游戏、失败与重开；
- 最佳成绩与尺寸偏好的本地持久化；
- 移动端布局与基本手势；
- 减少动态效果模式；
- 字体离线加载与外部依赖检查；
- 真实随机对局的端到端运行。

不在本轮范围：

- Safari / Firefox 实机测试；
- 正式 WCAG 合规审计；
- 低端设备长时性能与内存分析；
- 真实物理触屏设备测试；
- 后端、账号、排行榜（当前版本无后端）。

## 4. 随机对局端到端测试

### 4.1 方法

- 开启 `prefers-reduced-motion: reduce` 以加快测试节奏；
- 使用临时调试入口直接发起方向移动；
- 在 Python 侧固定随机种子，随机选择上 / 下 / 左 / 右；
- 最多执行 700 次迭代，直到失败弹窗出现；
- 检查弹窗内容、控制台错误和重新开始后的初始状态。

### 4.2 结果

| 项目 | 结果 |
| --- | --- |
| 出现失败弹窗 | 是 |
| 实际触发时迭代次数 | 第 64 次迭代 |
| 有效移动手数 | 48 |
| 分数 | 236 |
| 最高方块 | 32 |
| 失败弹窗标题 | 「无处可叠。」正常渲染与显示 |
| 点击另起一局后 | 回到 4 × 4、得分 0、2 枚方块、16 个格子 |
| 控制台错误 | 无 |

这说明移动循环、生成、可行移动判定、失败弹窗和重开流程在连续真实对局中能够协同工作。

## 7. 手动验收清单

以下清单可用于未来的版本回归。

### 7.1 基础流程

- [ ] 双击打开 `index.html`，页面在 2 秒内显示完整界面。
- [ ] 初始棋盘为上次选择的尺寸；首次打开默认为 4 × 4。
- [ ] 初始棋盘恰好 2 枚方块，互不重叠。
- [ ] 页面无外部网络请求。
- [ ] 浏览器控制台无错误。

### 7.2 移动与合并

- [ ] 四个方向键均能移动方块。
- [ ] W / A / S / D 与方向键行为一致。
- [ ] 鼠标拖动和触摸滑动均能触发方向移动。
- [ ] 一次移动中相同数字只合并一次。
- [ ] 合并后生成恰好 1 枚新方块。
- [ ] 无效方向不生成、不计分、不计手数。
- [ ] 动画期间重复输入不会造成重复生成或计分。
- [ ] 横向和纵向合并都正常。

### 7.3 分数与记录

- [ ] 合并得分等于新生成方块数值。
- [ ] 当前分数实时更新。
- [ ] 最佳成绩按尺寸独立记录。
- [ ] 刷新页面后最佳成绩和尺寸保持。
- [ ] 清除站点数据后记录归零。

### 7.4 胜利 / 失败

- [ ] 合出 1024 后显示胜利弹窗。
- [ ] 胜利弹窗显示本局得分与最高方块。
- [ ] 点击「继续叠山」后可以继续操作。
- [ ] 继续后再次合出更高方块不会重复弹胜利。
- [ ] 无空位且无可合并时显示失败弹窗。
- [ ] 失败弹窗只提供「另起一局」。
- [ ] 弹窗期间页面背景不可点击、不可 Tab 进入。
- [ ] 弹窗关闭后焦点回到合理位置。

### 7.5 响应式

- [ ] 390px 宽度下无横向滚动。
- [ ] 得分标签不会折成多行。
- [ ] 五格棋盘在手机上清晰可读。
- [ ] 短屏桌面仍能看到完整棋盘。
- [ ] 移动端显示简短操作提示。
- [ ] 按钮触控区域足够大。

### 7.6 无障碍与动效

- [ ] Tab 可以到达所有按钮与棋盘。
- [ ] 焦点环清晰可见。
- [ ] 开启“减少动态效果”后无长动画仍可正常操作。
- [ ] 读屏软件可以听到合并后得分、胜负和新局提示。
- [ ] 弹窗打开时焦点进入弹窗，关闭后恢复。
- [ ] `prefers-reduced-motion` 下游戏逻辑不出现等待卡顿。

### 7.7 数据异常

- [ ] 本地存储被禁用时游戏仍可运行。
- [ ] 手动写入非法 `dieshan.best.v1` 后刷新，成绩回退为 0。
- [ ] 手动写入非法 `dieshan.size.v1` 后刷新，棋盘回退为 4 × 4。

## 8. 已知问题与限制

1. **未进行跨浏览器实机回归**：测试环境为 Chromium / Microsoft Edge；Firefox 与 Safari 为设计兼容目标，但未在本轮验证。
2. **触摸测试为合成事件**：自动化中使用了 PointerEvent 模拟滑动，尚未在真实触屏设备上进行手感与误触评估。
3. **无正式无障碍审计**：焦点和读屏能力已实现基础测试，但未使用多款读屏软件进行完整审计。
4. **多标签页最佳成绩不合并**：已知限制，详见 [BACKEND.md](BACKEND.md#27-多标签页行为)。
5. **测试钩子未随发布**：由于发布版移除了调试入口，测试无法直接复现特定棋盘；功能验收需通过实际对局或临时测试构建完成。
6. **未包含文件协议存储差异测试**：`file://` 下不同浏览器的 `localStorage` 行为不同；推荐通过 HTTP 提供服务以获得稳定的持久化。
7. **没有持续集成**：当前没有自动化 CI 流程；每次发布需要重新运行回归检查。
